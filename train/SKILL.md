## 2. Шкала и формат оценки

- Каждый вопрос: **0–10** = балл за **точность** (попал в строгую формулировку) + балл за **глубину** (понимание системы вокруг). Вода и гавк баллов не дают.
- День из 5 вопросов = **макс 50**.
- В табло: `Очки / Из`, точность %, дней, вопросов. Профиль участника описывай словами (напр. «ровный охват», «силён в статистике, DL ноль», «острые пики + провалы»).

## 4. Рабочий цикл «дня»

0. **🔁 Повторение — модель billy: «5 новых/день + периодический спринт».** Billy сознательно выбрал (2026-06-20) **5 НОВЫХ вопросов каждый день, без ежедневного повтора**, а накопленное повторять **спринтами раз в ~1-2 недели** (не «пара месяцев» — иначе слишком много забывается). Причина — **психологическая устойчивость**: новизна каждый день = чувство прогресса = меньше пропусков (adherence > optimality, Fogg/Clear; «5 новых» держат запал лучше, чем «4 новых + 1 старый», который Billy отверг как демотивирующий «бег на месте»). НЕ навязывай ему ежедневный interleaving/«4+1» — это его явная отвергнутая опция. Балл «в свежей памяти» всё равно помечай как незакреплённый, пока вопрос не устоял на спринт-повторе. Сами спринты: короткие, по теме, можно адаптивно (трудные чаще). Контекст спора — в логе дня 2026-06-20.

1. **Вопросы.** Берёшь следующие 5 незанятых сверху из [банка](~/Documents/billynotes/ML/trainchat/банк-вопросов.md) (он отсортирован по популярности на собесах). Постишь в чат одним сообщением «⚖️ СУД КЛОДА — СЛЕПОЙ ЗАМЕР» + `#train` + правила (без нейронки, без подглядывания).
2. **Эталоны — себе.** Сразу держишь правильные ответы (в файле дня), участникам не показываешь.
3. **Сбор + оценка.** По мере ответов — `get_messages`, оцениваешь каждого, постишь «⚖️ СУД КЛОДА — ответы @user» с баллами и разбором (`#train`).
4. **Табло + лог + досье.** Обновляешь `таблица-очков.md` (строка дня + пересчёт лидерборда + «кто какие № банка закрыл») и `дни/ГГГГ-ММ-ДД.md` (ответы + баллы + итог). Помечаешь заданные вопросы `✅ ГГГГ-ММ-ДД` в банке. **И ОБЯЗАТЕЛЬНО на КАЖДОГО ответившего:**

5. **Финал дня.** Когда все сдали (или забили) — раскрываешь эталоны в чат + блок «Финал» в файле дня (лидерборд, лучшие ответы, общие дыры группы, рекомендация).

## 5. Эталоны как .md-файлы с формулами (фишка рубрики)

Telegram рендерит markdown с LaTeX (как Obsidian), поэтому детальные разборы шлём **файлами .md**, а не текстом.

**Формат эталон-файла** (`эталоны/Q* — тема.md`): первая строка `#train`, заголовок `# Q* — …`, блок-цитата с вопросом, разделы по первым принципам, формулы в `$...$` / `$$...$$`, «📌 Одной строкой» в конце. Cyrillic держать ВНЕ математики (в `\text{}` ломается) — обозначай данные как `$D$` и т.п. Образцы — это файлы в `эталоны/` (Q1–Q5 за 2026-06-20).

**Отправка файлов в чат** (бот в группе не состоит, MCP шлёт только текст → шлём от user-аккаунта Billy через telethon, кратко погасив MCP-сервис):

```sh
~/.Codex/skills/train/scripts/send-files.sh -1003179772905 \
  "/path/Q1 — ....md" "/path/Q2 — ....md" ...
```

Скрипт: `bootout com.billy.telegram-mcp` → `telethon send_file` (force_document, подпись с `#train` авто) → `bootstrap` обратно. Так избегаем AuthKeyDuplicated. После — `get_messages` для проверки + `cp` файлов в `эталоны/`.
